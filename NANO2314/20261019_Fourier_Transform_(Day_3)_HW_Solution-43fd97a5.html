  1. 1. (5 pts) By eye.

    1. Plot deflection versus time for the first 50 µs, using Excel, Google Colab, or another plotting tool. Attach or upload your graph.

    2. Estimate the periods T1T_1 (large, slow oscillation) and T2T_2 (small, fast ripple). Tip: time several cycles and divide by the number of cycles.

    3. Calculate f1=1/T1f_1 = 1/T_1 and f2=1/T2f_2 = 1/T_2 in kHz. Is f2/f1f_2/f_1 close to 6.27, the value for a rectangular cantilever?

    Solution for question 1

    (a) Plot deflection_nm against time_us for the rows with time up to 50 µs (the first 501 rows).

    (b) and (c)

    T1≈45µs−3µs3=14µs,T2≈49µs22≈2.2µsT_1 \approx \frac{45\ \text{µs} - 3\ \text{µs}}{3} = 14\ \text{µs}, \qquad T_2 \approx \frac{49\ \text{µs}}{22} \approx 2.2\ \text{µs}

    Why: measuring across several cycles and dividing spreads your reading error over all of them.

    ↓ invert each period

    f1=1T1≈114µs≈0.071µs−1=71kHzf_1 = \frac{1}{T_1} \approx \frac{1}{14\ \text{µs}} \approx 0.071\ \text{µs}^{-1} = 71\ \text{kHz}

    Why: 1µs−1=106Hz=1000kHz1\ \text{µs}^{-1} = 10^{6}\ \text{Hz} = 1000\ \text{kHz}.

    ↓ same for the ripple

    f2=1T2≈12.2µs≈0.45µs−1=450kHzf_2 = \frac{1}{T_2} \approx \frac{1}{2.2\ \text{µs}} \approx 0.45\ \text{µs}^{-1} = 450\ \text{kHz}

    ↓ divide the two frequencies

    Conclusion

    f2f1≈450kHz71kHz≈6.3≈6.27\frac{f_2}{f_1} \approx \frac{450\ \text{kHz}}{71\ \text{kHz}} \approx 6.3 \approx 6.27

    In words. Three slow cycles take about 42 µs and 22 ripple cycles take about 49 µs, so f1≈71kHzf_1 \approx 71\ \text{kHz} and f2≈450kHzf_2 \approx 450\ \text{kHz}. Their ratio, about 6.3, matches the 6.27 expected for the second mode of a rectangular cantilever.

    By-eye answers within about 10% (e.g. f1f_1 from 64 to 79 kHz, f2f_2 from 400 to 500 kHz) are fine.

    Sample script (Python; runs in Google Colab after you upload 261021-bimodal_AFM-data.csv; saved as problem1_by_eye.py):

    import numpy as np
import matplotlib.pyplot as plt

# In Google Colab, first upload the CSV (Files panel on the left)
t, x = np.loadtxt("261021-bimodal_AFM-data.csv", delimiter=",",
                  skiprows=1, unpack=True)    # t in µs, x in nm

m = t <= 50                                   # the first 50 µs
plt.figure(figsize=(10, 4))
plt.plot(t[m], x[m], ".-", ms=3, lw=0.8)
plt.xlabel("time (µs)")
plt.ylabel("deflection (nm)")
plt.xticks(np.arange(0, 51, 5))
plt.grid(alpha=0.4)
plt.show()

# Read crests off the graph, then measure across several cycles:
T1 = (45 - 3) / 3      # slow crests near 3 µs and 45 µs: 3 cycles
T2 = 49 / 22           # 22 ripple cycles from about 0 µs to 49 µs
f1 = 1e3 / T1          # kHz  (1/µs = 1000 kHz)
f2 = 1e3 / T2
print(f"T1 = {T1:.1f} µs  ->  f1 = {f1:.0f} kHz")
print(f"T2 = {T2:.2f} µs  ->  f2 = {f2:.0f} kHz")
print(f"f2/f1 = {f2 / f1:.2f}  (rectangular cantilever: 6.27)")

  2. 2. (5 pts) By Fourier transform.

    1. Use Google Colab or another AI-assisted tool to Fourier-transform all 500 µs of data (using all of it gives the best resolution). Plot the spectrum from 0 to 1000 kHz, and read f1f_1 and f2f_2 from the two peaks. Attach or upload your graph.

    2. Zoom in on one peak. What is the spacing between neighboring frequency points (the frequency resolution)?

    3. Compare your f1f_1 and f2f_2 from Problems 1 and 2. Which method is more precise?

    Solution for question 2

    (a) In Python: X = numpy.fft.rfft(x) and f = numpy.fft.rfftfreq(5000, 0.1e-6), then plot 2*abs(X)/5000 against f/1000 (kHz). There are two peaks, at 72 kHz and 448 kHz.

    (b) Zoomed in, the spectrum is a set of separate points, not a smooth curve:

    Trecord=5000×0.1µs=500µsT_{\text{record}} = 5000 \times 0.1\ \text{µs} = 500\ \text{µs}

    ↓ spacing is one over the record length

    Δf=1Trecord=1500µs=0.002µs−1\Delta f = \frac{1}{T_{\text{record}}} = \frac{1}{500\ \text{µs}} = 0.002\ \text{µs}^{-1}

    Why: the FFT only tests frequencies that fit a whole number of cycles into the record: 1/Trecord1/T_{\text{record}}, 2/Trecord2/T_{\text{record}}, and so on.

    ↓ convert to kHz

    Conclusion

    Δf=2kHz\Delta f = 2\ \text{kHz}

    In words. The frequency points are 1/(500µs)=2kHz1/(500\ \text{µs}) = 2\ \text{kHz} apart, so a peak can be read to about ±1kHz\pm 1\ \text{kHz} (half the spacing): f1=72±1kHzf_1 = 72 \pm 1\ \text{kHz} and f2=448±1kHzf_2 = 448 \pm 1\ \text{kHz}.

    (c)

    Method f1f_1 f2f_2
    By eye about 71 kHz (± 3 kHz or so) about 450 kHz (± 20 kHz or so)
    By Fourier transform 72 ± 1 kHz 448 ± 1 kHz

    The Fourier transform is more precise. Its uncertainty is set by the 2 kHz point spacing, not by how well you can read a noisy curve, and it needs no guessing. The two methods agree within the by-eye uncertainty.

    Sample script (Python; runs in Google Colab after you upload 261021-bimodal_AFM-data.csv; saved as problem2_fourier.py):

    import numpy as np
import matplotlib.pyplot as plt

t, x = np.loadtxt("261021-bimodal_AFM-data.csv", delimiter=",",
                  skiprows=1, unpack=True)    # t in µs, x in nm

N = len(x)                          # 5000 points
dt = (t[1] - t[0]) * 1e-6           # 0.1 µs, in seconds
X = np.fft.rfft(x)                  # Fourier transform of the whole record
f = np.fft.rfftfreq(N, dt) / 1e3    # frequencies, in kHz
A = 2 * np.abs(X) / N               # magnitude, in nm

plt.figure(figsize=(10, 4))
plt.plot(f, A)
plt.xlim(0, 1000)
plt.xlabel("frequency (kHz)")
plt.ylabel("|X(f)| (nm)")
plt.show()

df = f[1] - f[0]                    # spacing between frequency points
print(f"spacing between frequency points: {df:.1f} kHz")
for lo, hi in [(20, 200), (300, 600)]:          # a window around each peak
    s = (f > lo) & (f < hi)
    print(f"peak at {f[s][np.argmax(A[s])]:.0f} ± {df / 2:.0f} kHz")

s = (f > 60) & (f < 84)             # zoom on the first peak
plt.plot(f[s], A[s], "o-")
plt.xlabel("frequency (kHz)")
plt.ylabel("|X(f)| (nm)")
plt.show()

  3. 3. (5 pts) [Extra credit, up to 5 points] By curve fitting.

    1. Using Google Colab or another AI-assisted tool, curve-fit the first 50 µs of data. What is the fit function that fits the data well? Attach or upload your graph. (Hint 1: include a phase for each frequency. Hint 2: use your by-eye f1f_1 and f2f_2 as initial guesses. Hint 3: also give initial guesses for the amplitudes A1A_1 and A2A_2.)

    2. How do your fitted f1f_1 and f2f_2 compare with Problems 1 and 2? How precise are they (give the uncertainties)?

    3. What information can you get from curve fitting that you cannot get from the Fourier transform?

    Solution for question 3

    (a) The function that fits is a sum of two sines, each with its own amplitude, frequency and phase:

    x(t)=A1sin⁡(2πf1t+δ1)+A2sin⁡(2πf2t+δ2)x(t) = A_1 \sin(2\pi f_1 t + \delta_1) + A_2 \sin(2\pi f_2 t + \delta_2)

    Fitting the first 50 µs (501 points), starting from f1=70kHzf_1 = 70\ \text{kHz} and f2=450kHzf_2 = 450\ \text{kHz}, with amplitudes read off the graph (A1=20nmA_1 = 20\ \text{nm}, A2=5nmA_2 = 5\ \text{nm}), gives:

    Parameter Fit value Uncertainty (1σ)
    A1A_1 19.95 nm 0.08 nm
    f1f_1 71.56 kHz 0.04 kHz
    δ1\delta_1 15.2° 0.4°
    A2A_2 4.96 nm 0.08 nm
    f2f_2 448.98 kHz 0.17 kHz
    δ2\delta_2 80.8° 1.8°

    If time is in µs, the fitted frequencies come out in µs⁻¹, i.e. MHz (0.07156MHz=71.56kHz0.07156\ \text{MHz} = 71.56\ \text{kHz}). If the fit misses the fast ripple, the starting f2f_2 was too far off. Move it closer, or start from the Fourier-transform values, which almost always work.

    (b)

    Method f1f_1 (kHz) f2f_2 (kHz)
    By eye about 71 (± 3) about 450 (± 20)
    Fourier transform 72 ± 1 448 ± 1
    Curve fit (50 µs) 71.56 ± 0.04 448.98 ± 0.17

    All three agree within their uncertainties. The fit is the most precise: about 25 times better than the Fourier transform for f1f_1 and about 6 times better for f2f_2. It can beat the 2 kHz point spacing because it uses the full shape of the curve, but it needs good starting guesses, which the first two methods provide.

    (c) The phases. The fit gives δ1≈15∘\delta_1 \approx 15^{\circ} and δ2≈81∘\delta_2 \approx 81^{\circ}, so the fast mode leads the slow one by δ2−δ1≈66∘\delta_2 - \delta_1 \approx 66^{\circ}. The magnitude spectrum |X(f)||X(f)| throws the phase away. That is why two signals with different shapes can have the same spectrum, as in lecture. The fit also gives the amplitudes (20.0 nm and 5.0 nm) directly, each with an uncertainty. The plain FFT peak heights (about 19 nm and 3.5 nm) come out low, because the true frequencies fall between the 2 kHz points.

    Sample script (Python; runs in Google Colab after you upload 261021-bimodal_AFM-data.csv; saved as problem3_fit.py):

    import numpy as np
import matplotlib.pyplot as plt
from scipy.optimize import curve_fit

t, x = np.loadtxt("261021-bimodal_AFM-data.csv", delimiter=",",
                  skiprows=1, unpack=True)    # t in µs, x in nm
m = t <= 50                                   # fit the first 50 µs

def model(t, A1, f1, d1, A2, f2, d2):         # t in µs, so f in MHz
    return (A1 * np.sin(2 * np.pi * f1 * t + d1)
            + A2 * np.sin(2 * np.pi * f2 * t + d2))

# initial guesses: amplitudes from the graph, frequencies from Problem 1
guess = [20, 0.070, 0, 5, 0.450, 0]          # nm, MHz, rad, nm, MHz, rad
p, cov = curve_fit(model, t[m], x[m], p0=guess)
err = np.sqrt(np.diag(cov))

names = ["A1 (nm)", "f1 (MHz)", "d1 (rad)", "A2 (nm)", "f2 (MHz)", "d2 (rad)"]
for name, value, e in zip(names, p, err):
    print(f"{name:9s} = {value:.5f} ± {e:.5f}")
print(f"phase difference d2 - d1 = {np.degrees(p[5] - p[2]) % 360:.0f} degrees")

tt = np.linspace(0, 50, 3000)
plt.figure(figsize=(10, 4))
plt.plot(t[m], x[m], ".", color="gray", label="data")
plt.plot(tt, model(tt, *p), "r-", label="fit")
plt.xlabel("time (µs)")
plt.ylabel("deflection (nm)")
plt.legend()
plt.show()
